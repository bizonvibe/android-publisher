# Android Instagram Reels Publisher

Первый локальный Reels: **мастер → проверка R2 → USB → интерактивный DRY_RUN → остановка перед Share**. Python 3.11+, Windows, физический Android, ADB и UIAutomator2. Без Instagram Graph API.

Сейчас реальную публикацию запускать не нужно. LIVE по умолчанию выключен и мастер его не включает. Телефон и Windows не подключены к облачному окружению: аппаратная совместимость будет проверена вашим первым локальным DRY_RUN. Mock-тесты не заменяют эту проверку.

## Самый короткий путь на Windows

1. Установите [Python 3.11/3.12](https://www.python.org/downloads/windows/), Git и официальные [Android Platform Tools](https://developer.android.com/tools/releases/platform-tools). Распакуйте Platform Tools; мастер спросит путь к `adb.exe`, если его нет в PATH. При необходимости установите USB-драйвер производителя.
2. На телефоне включите режим разработчика и **USB debugging**, подключите кабель с передачей данных, разблокируйте экран и подтвердите RSA-ключ компьютера. В Instagram вручную войдите в нужный аккаунт и разрешите доступ к видео. Завершите 2FA/проверки личности вручную.
3. Откройте PowerShell в каталоге репозитория:

```powershell
git clone https://github.com/bizonvibe/android-publisher.git
cd android-publisher
git switch fix/first-android-reel
.\scripts\Start-Publisher.ps1
```

Если Windows блокирует запуск скрипта, не меняйте глобальную policy: используйте `powershell -ExecutionPolicy Bypass -File .\scripts\Start-Publisher.ps1` для этого одного проверенного скрипта либо выполните эквивалент вручную:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m android_publisher setup
```

Мастер автоматически выберет единственное устройство со статусом `device`, спросит username, R2 endpoint/account ID и режим Trial/NORMAL. Он создаст локальные файлы сам: не нужно редактировать большой профиль или JSON задания. Если устройств несколько, попросит serial. При `unauthorized` подтвердите RSA на телефоне; при `offline` переподключите кабель. Проверка вручную: `adb devices -l`.

Ваши готовые значения уже подставлены по умолчанию:

- Bucket: `content-factory-videos`.
- MP4: `reels/ru/reel-20261109-92645916/video.mp4`.
- Manifest: `reels/ru/reel-20261109-92645916/manifest.json`.

**Ключи R2 мастер спрашивает скрытым вводом и держит только в памяти процесса.** Либо заранее задайте их в защищённом окружении Windows. В `publisher.local.json` записываются только USB serial, путь ADB, путь профиля, endpoint и bucket. Ключи, API-токен и разрешение LIVE туда не попадают. При следующем запуске ключи надо снова передать через ENV или скрытый ввод. Не вставляйте секреты в Git/чат/CLI-аргументы. Read-only GetObject достаточно; ListBucket/запись/публичный bucket не требуются.

Мастер скачает и проверит manifest/MP4 по фактическому формату фабрики, MIME, SHA256 и размеру. Пустое описание означает предложение загрузить проверенное `assets.description` из R2; текст будет показан для сверки. Затем мастер предложит **только DRY_RUN**.

## Интерактивный DRY_RUN на телефоне

```powershell
.\scripts\Start-Publisher.ps1 -Command dry-run
```

Или напрямую, с выбором режима без изменения JSON:

```powershell
.\.venv\Scripts\python.exe -m android_publisher dry-run --job data/first-job.json --mode TRIAL_REEL --interactive
.\.venv\Scripts\python.exe -m android_publisher dry-run --job data/first-job.json --mode NORMAL_REEL --interactive
```

Запускайте по одному, при остановленном API. Перед новым прогоном вручную закройте прежний неподтверждённый черновик, если Instagram показывает его. **Не нажимайте Share вручную во время DRY_RUN.** Оставляйте телефон разблокированным, не переключайте аккаунт; интернет нужен самому Instagram.

При первом неизвестном элементе мастер покажет номер шага, список доступных элементов экрана с надписями/состоянием и сохранит screenshot/XML. Выберите номер и введите `SAVE`. Это сохраняет селектор **без нажатия выбранного элемента**; затем сценарий выполняет только разрешённый подготовительный шаг. `r` обновляет список после вашего ручного перехода к нужному экрану. `q` останавливает работу.

Селекторы используют resource ID, accessibility description, текст либо XPath с устойчивым родителем для одинаковых переключателей; экранные координаты в профиль не записываются. Неоднозначное совпадение останавливает процесс. Промежуточный шаг с кнопкой Share/Опубликовать блокируется даже при ошибочной калибровке. Не назначайте финальную кнопку на Next/Далее.

Особенности текущего Instagram:

- После USB-передачи SHA256 повторно проверяется на телефоне. Мастер импортирует **точно переданный файл** через Android MediaStore URI и ACTION_SEND с разрешением чтения для Instagram. Это не публикация. Выберите Reels в меню импорта. Если Instagram сразу открыл редактор, для отсутствующего промежуточного `reel` можно указать `skip`; аналогично отсутствующему экрану Next. Финальную кнопку, аккаунт, описание и проверку режима пропустить нельзя. Если системный диалог мешает, выберите Instagram/разрешите видео вручную и повторите DRY_RUN.
- `trial_toggle` должен указывать на checkable-переключатель. Если Trial недоступен вашему аккаунту, укажите `absent`: TRIAL_REEL завершится `FEATURE_UNAVAILABLE`. **Обычный ролик вместо Trial не отправляется.** Для NORMAL при наличии Trial проверяется выключенное состояние.
- В Trial автоматическое распространение отключается и проверяется. Если настройка скрыта в дополнительном меню, вручную откройте его при запросе соответствующего шага и выберите переключатель. При последующем запросе marker вернитесь на экран подготовки. Если состояние нельзя надёжно прочитать, сценарий остановится — обхода нет.
- Для `trial_mode_marker`/`normal_mode_marker` можно выбрать сам переключатель: мастер привяжет селектор к его текущему checked-состоянию. Либо выберите однозначную надпись режима. Не выбирайте общий заголовок/кнопку Share вместо проверки режима.
- Username считывается с профиля. Если Instagram не показывает его на финальном экране, для `composer_account` предусмотрен `owner`: владелец вручную сверяет аккаунт и вводит точное `@username`. Эта проверка требует присутствия и не разрешает фоновую публикацию через API.
- Для `publish` выбирается **финальная** кнопка, но DRY_RUN её не нажимает.

Результат `DRY_RUN_READY` означает: файл подготовлен, caption проверен, режим/аккаунт проверены, сценарий остановлен перед финальным действием. Артефакты: `data/jobs/<UUID>/screen.png`, `hierarchy.xml`, `steps/<номер>-<шаг>/...`, `download.json`. При остановке `stop.json` содержит последний шаг, безопасный код причины и инструкцию исправления. Сохраните UUID успешного прогона.

Для отдельной перекалибровки, открыв нужный экран на телефоне:

```powershell
.\.venv\Scripts\python.exe -m android_publisher calibrate --step publish
```

Профиль сохраняется в `profiles/instagram-local.json`; калибровка не выставляет `live_calibrated=true`. Изменение Instagram, профиля или телефона требует нового DRY_RUN. Не редактируйте флаг LIVE ради прохождения DRY_RUN.

## Диагностика и исправления

```powershell
.\scripts\Start-Publisher.ps1 -Command doctor
```

Или `python -m android_publisher doctor --job data/first-job.json --download`. Проверяются версии Python/пакетов, ADB, serial/authorization, наличие Instagram, UIAutomator2, состояние экрана, профиль, реальное чтение manifest и MP4 из R2 с SHA256/MIME. `doctor` не запускает Instagram, не публикует и не пишет в R2. UIAutomator2 при первом подключении может установить свой обычный компонент управления на Android; подтвердите запросы телефона. `doctor` без `--download` не объявляет проверку MP4 успешной. Отчёт: `data/doctor-report.json`.

При проблемах сначала прочитайте `fix` в отчёте/`stop.json`. При капче, входе, проверке личности или блокировке работа прекращается, очередь ставится на постоянную паузу. Решайте запрос вручную в Instagram; не отключайте защиту и не обходите ограничения. Только после проверки: `python -m android_publisher resume`, затем новый DRY_RUN. Resume не повторяет `UNKNOWN_RESULT` или завершённые задания.

Файлы скриншотов/XML могут содержать персональные данные; ограничьте доступ к `data/` средствами Windows. Видео и результаты хранятся локально, автоматическая очистка не включена. Не удаляйте SQLite ради повторной отправки: она хранит защиту от дублей. Для backup используйте SQLite backup при обслуживании, а не копирование живого файла без WAL.

## Подготовленный путь LIVE — сейчас не запускать

Отдельная локальная команда существует для будущего разрешения владельца. Она работает только с успешным DRY_RUN из той же базы не старше 30 минут. Проверяются тот же телефон, версия Instagram, SHA256 профиля и повторно скачанные байты видео. `PUBLISHER_ALLOW_LIVE` должен быть **явно** установлен владельцем в окружении; ни setup, ни калибровка его не выставляют.

После разрешения команда `python -m android_publisher live --from-dry-run <UUID>` заново подготовит ролик, покажет аккаунт, режим, caption, SHA256 и screenshot. **Перед финальным нажатием** потребует точную фразу `PUBLISH @username TRIAL_REEL` либо `... NORMAL_REEL`. Enter/yes/отмена не разрешают публикацию. Подтверждение сохраняется отдельно. Такое задание не может автоматически выполниться после рестарта/через API без владельца.

Если настроен однозначный `publication_success`, результат проверяется по нему. Если UI не предоставляет надёжного маркера, локальный режим просит владельца открыть именно опубликованный ролик, скопировать permalink и отдельно подтвердить результат. Это записывается как `verification=owner-confirmed`, а не автоматическое доказательство. Пустой/некорректный permalink или отказ → `UNKNOWN_RESULT`, без повторного нажатия. Уведомление ленты само по себе не считается успехом. Эта возможность не нужна для текущего DRY_RUN и здесь не использовалась для реальной публикации.

Перед финальным действием SQLite одной транзакцией резервирует `(account_id,video_id)` и `(account_id,SHA256)`, фиксирует `submitted=1`. Смена video ID/ключа задания не позволяет повторить те же байты. Финальная кнопка находится уникальным селектором; единственный ADB tap использует её текущие bounds, без повторов JSON-RPC. Сбой после отправки или рестарт в SUBMITTING → UNKNOWN_RESULT и пауза устройства. Это консервативное «не более одной попытки», не exactly-once гарантия внешнего Instagram.

## Совместимость manifest/R2

Текущий экспортёр реально проверен в `insta-reels-agent`, **ветка feature/ru-reels-r2**. Он создаёт `assets.video.{key,sha256,bytes,content_type}`, а не плоскую схему предыдущего MVP. Подробности, commit, ссылки, исходный SHA256 вашего ролика и ограничения проверки — [docs/MANIFEST_COMPATIBILITY.md](docs/MANIFEST_COMPATIBILITY.md).

Поддержаны `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`, `R2_ENDPOINT` либо `R2_ACCOUNT_ID`, как в генераторе. Эквиваленты `PUBLISHER_R2_*` из [.env.example](.env.example) имеют приоритет. `.env` автоматически не читается; секреты только ENV/память процесса. Новое поле задания `r2_manifest_key` позволяет явно выбрать фактический manifest. Старый плоский контракт и проверенные legacy QA-форматы сохранены для совместимости.

## API и сохранённая надёжность

`python -m android_publisher serve` запускает FastAPI на `127.0.0.1:8080` с одним worker. Для API отдельно задайте `PUBLISHER_API_TOKEN`; все методы требуют `Authorization: Bearer ...`. Интерактивный мастер использует локальный worker напрямую, API для первой публикации запускать не нужно. Одновременная работа CLI/API на одном телефоне блокируется общей OS-блокировкой. Один телефон — одна база/один Windows-пользователь. Другие ADB-автоматизации во время работы не запускайте.

- `POST /v1/jobs`: video_id, r2_object_key, необязательный r2_manifest_key, account_id (username без @), caption, publication_mode, scheduled_at с timezone, idempotency_key, execution_mode (по умолчанию DRY_RUN).
- `GET /v1/jobs/{id}`: статус, результат, инструкции, пути артефактов.
- `GET /health`: worker, пауза, ADB, разрешение LIVE. Health не заменяет doctor.
- `POST /v1/device/resume`: явное снятие паузы после ручной проверки.

Режимы: TRIAL_REEL, NORMAL_REEL и отдельный SHARE_TRIAL_TO_EVERYONE. Перевод требует source_job_id успешно опубликованного LIVE Trial того же аккаунта/video/key и сохранённый permalink. Штатная функция отсутствует → FEATURE_UNAVAILABLE. Автоматический перевод Trial никогда не включается. Локальный путь первого LIVE поддерживает свежий DRY_RUN первоначальной публикации; для перевода используйте отдельный API-контракт после калибровки соответствующих экранов.

API для полностью автоматического LIVE по-прежнему требует явного ENV-разрешения, `execution_mode=LIVE`, полного UI-профиля `live_calibrated=true` и маркера успеха. Профиль с owner-проверками предназначен для локального присутствия, он не становится автоматически готовым для фонового API. Повторы одного idempotency_key возвращают прежнее задание; иное содержимое даёт409. LIVE без ENV-разрешения даёт403. Временные ошибки повторяются только до барьера, максимум3 раза (настраивается); UI/капча/неизвестный исход не повторяются. WAL + synchronous=FULL, восстановление после рестарта сохраняется. Appium остаётся альтернативным адаптером, но для первого USB-телефона не требуется.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[test]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
```

CI: Ubuntu/Windows × Python 3.11/3.12, Mock Android и Mock R2, без реальных публикаций. Тесты включают фактический R2-контракт из кода экспортёра и сохранённого upstream-отчёта, legacy fixtures, MIME/SHA256, мастер без сохранения секретов, калибровку без кликов, MediaStore URI, оба DRY_RUN, подтверждение владельца и защиту LIVE после рестарта, дедупликацию по видео/SHA256, остановки и диагностику. Физический Android и приватный R2 из этого облачного окружения не проверены; первый аппаратный результат — ваш локальный DRY_RUN.
