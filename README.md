# Android Instagram Reels Publisher

Локальный MVP на Python 3.11+ для Windows: FastAPI → SQLite → приватный Cloudflare R2 → ADB по USB → UIAutomator2 → приложение Instagram. Instagram Graph API не используется. Один worker обслуживает один явно указанный телефон и проверяет имя аккаунта. Генерация видео и расписание контента остаются в `insta-reels-agent` и `content-orchestrator`.

**По умолчанию только DRY_RUN.** Реальные экраны на физическом телефоне в этом репозитории не проверены. Профиль `profiles/instagram-en.example.json` — намеренно неполный пример, а не готовый универсальный драйвер Instagram. До настройки селекторов под вашу версию приложения сервис остановится с диагностикой. Mock-тесты проверяют логику, но не доказывают совместимость с Instagram.

## Установка Windows и подключение USB

1. Установите Python 3.11 или 3.12, Git и официальные [Android SDK Platform Tools](https://developer.android.com/tools/releases/platform-tools). Добавьте каталог с `adb.exe` в `PATH` либо задайте `PUBLISHER_ADB_PATH` полным путём. При необходимости установите USB-драйвер производителя телефона.
2. На Android включите режим разработчика (обычно семь нажатий на «Номер сборки»), затем «Отладка по USB». Подключите телефон кабелем с передачей данных. Разблокируйте экран и подтвердите RSA-ключ компьютера. При необходимости выберите USB-режим передачи файлов.
3. Выполните `adb devices -l`. Нужна строка `SERIAL device`, а не `unauthorized` или `offline`. Запишите serial. Используется только USB: ADB по сети не включается.
4. Установите Instagram, вручную войдите в нужный аккаунт, завершите 2FA и запросы подтверждения. Разрешите доступ к фото/видео. Оставляйте телефон разблокированным, с включённым экраном и стабильным интернетом. Во время работы не переключайте аккаунт и не управляйте приложением вручную.
5. Подготовьте проект в PowerShell:

```powershell
git clone https://github.com/bizonvibe/android-publisher.git
cd android-publisher
git switch feature/android-instagram-publisher
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
$env:PUBLISHER_DEVICE_SERIAL = "YOUR_SERIAL"
adb -s $env:PUBLISHER_DEVICE_SERIAL get-state
```

UIAutomator2 при первом подключении устанавливает необходимые компоненты на телефон; подтвердите запросы Android. Некоторые прошивки требуют отдельного разрешения установки/управления через USB. Не отключайте защиту аккаунта и не пытайтесь обходить ограничения Instagram.

## Секреты и запуск

Все параметры читаются из переменных окружения с префиксом `PUBLISHER_`. `.env.example` — справочник; `.env` автоматически **не читается**. Не помещайте ключи в Git, задания, скриншоты или логи. Используйте переменные процесса/защищённое хранилище вашего Windows-пользователя.

```powershell
$env:PUBLISHER_API_TOKEN = "YOUR_RANDOM_BEARER_TOKEN"
$env:PUBLISHER_R2_ENDPOINT_URL = "https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com"
$env:PUBLISHER_R2_ACCESS_KEY_ID = "YOUR_READ_ONLY_R2_KEY"
$env:PUBLISHER_R2_SECRET_ACCESS_KEY = "YOUR_R2_SECRET"
$env:PUBLISHER_R2_BUCKET = "content-factory-videos"
$env:PUBLISHER_ALLOW_LIVE = "false"
$env:PUBLISHER_SELECTOR_PROFILE = "profiles/instagram-local.json"
python -m android_publisher
```

API слушает только `127.0.0.1:8080`, один Uvicorn worker, без reload. Bearer-токен обязателен, в том числе для health. Swagger: `http://127.0.0.1:8080/docs`. Не публикуйте API в интернет. Для удалённого оркестратора используйте защищённый канал до Windows и аутентификацию; никаких секретов в URL. `account_id` здесь — **точное Instagram username**, без `@`, а не числовой Graph API ID.

Создайте профиль до запуска по инструкции ниже. Для теста без телефона можно задать `PUBLISHER_ANDROID_BACKEND=mock`, но загрузка из R2 остаётся настоящей. Полностью автономные CI-тесты подменяют и Android, и R2. Mock-backend не допускает включение LIVE.

## Калибровка селекторов: обязательный шаг

Скопируйте `profiles/instagram-en.example.json` в `profiles/instagram-local.json`. Пустые списки означают, что шаг ещё не настроен; координатного fallback нет. Профиль содержит селекторы UIAutomator2: `resourceId`, `description`, `text` и другие разрешённые поля. Каждый шаг должен совпадать ровно с одним элементом; несколько совпадений останавливают задание.

При остановленном сервисе вручную откройте очередной экран Instagram и выполните:

```powershell
python -m android_publisher.inspect
```

Команда сохраняет текущие `screen.png` и `hierarchy.xml` в `data/inspection/`, ничего не нажимая. Изучите XML, подставьте точные resource IDs/accessible descriptions для вашей версии и языка. Не используйте `text=Share` без проверки контекста. Альтернативы предназначены для разных версий UI: одновременно должен совпадать только один селектор. Дополните список `blockers` локализованными сообщениями о капче, входе, ограничениях и проверке личности.

Проверьте все шаги:

- `profile_tab` → `account_username`: username выбранного аккаунта.
- `create` → `reel` → `gallery` → **точное имя файла** `<job-uuid>.mp4` через accessibility description → `gallery_next` → `editor_next` → `caption`. Телефон получает файл в `/sdcard/Movies/Publisher/`. Если галерея не предоставляет имя файла через accessibility, текущий адаптер остановится `EXACT_MEDIA_NOT_FOUND`: потребуется доработать выбор по доступным метаданным конкретной галереи. Выбор первого/новейшего файла запрещён.
- `trial_toggle` и `automatic_share_toggle` должны указывать непосредственно на checkable-элементы с состоянием `checked`. Для Trial автоматическое распространение выключается и проверяется. Если этот параметр скрыт за дополнительным экраном, текущий адаптер нужно адаптировать под него; публикация до этого блокируется.
- `trial_mode_marker` и `normal_mode_marker` однозначно подтверждают режим. `composer_account` повторно подтверждает username на экране перед публикацией. Если версия Instagram не раскрывает эти данные, LIVE безопасно блокируется.
- `publish` — финальное подтверждение. `publication_success` — явное подтверждение результата именно отправленного ролика, а не вкладка ленты/профиля. Маркер не должен существовать до финального нажатия. Если такого подтверждения получить не удалось, результат будет `UNKNOWN_RESULT`, а не «успех».
- `published_permalink` необязателен для обычной публикации; если есть, должен вернуть текст полного `https://www.instagram.com/reel/SHORTCODE/`. Для последующего перевода Trial нужна эта сохранённая ссылка. Если UI не предоставляет её, перевод текущим адаптером блокируется `SOURCE_PERMALINK_UNAVAILABLE`.
- Для перевода Trial настройте `existing_trial_marker`, `existing_reel_owner`, `trial_options`, `share_everyone_prepare` (открывает подтверждение) и `share_everyone_confirm` (финальное действие). Не назначайте финальную кнопку на подготовительный шаг.

Запустите DRY_RUN отдельно для обычного и пробного ролика и проверьте телефон/сохранённый скриншот. Только после ручной сверки всех переходов, кнопок и подтверждения успеха установите в локальном профиле `live_calibrated: true`. Обновление Instagram требует повторной проверки. Этот флаг — ручное подтверждение настройки, а не автоматическая сертификация.

Appium рассмотрен как альтернатива: он даёт WebDriver и поддержку device farm, но для одного USB-телефона добавляет сервер, драйвер и настройку Android SDK. UIAutomator2 проще для локального Windows MVP. Интерфейс `Android.prepare/submit/health/evidence` позволяет добавить Appium-адаптер позднее без изменения очереди.

## Контракт R2

Создайте read-only S3-совместимый ключ только для приватного bucket `content-factory-videos`. Публичный доступ и presigned URL не нужны. Для ключа `reels/reel-001/video.mp4` сервис читает `reels/reel-001/manifest.json`:

```json
{
  "video_id": "reel-001",
  "object_key": "reels/reel-001/video.mp4",
  "sha256": "64 hex characters of the real MP4 SHA256",
  "size_bytes": 123456
}
```

Вычислите хеш: `(Get-FileHash video.mp4 -Algorithm SHA256).Hash.ToLower()`, размер: `(Get-Item video.mp4).Length`. Сначала загрузите MP4, затем manifest. Объекты после постановки задания должны быть неизменяемыми: используйте уникальный prefix на `video_id`. Сервис проверяет идентификатор, точное имя объекта, размер и SHA256 потокового скачивания; только затем передаёт файл телефону. Manifest ограничен 64 KiB, видео — 1 GiB. Пример `examples/manifest.json` требует замены хеша/размера.

## API и операции

`POST /v1/jobs` создаёт задание; `GET /v1/jobs/{id}` возвращает состояние, результат и пути артефактов. `GET /health` показывает worker, паузу, ADB и разрешение LIVE; ADB health не гарантирует корректность текущего экрана Instagram. `POST /v1/device/resume` снимает паузу устройства после вашей ручной проверки, но не повторяет завершённые задания.

```powershell
$headers = @{ Authorization = "Bearer $env:PUBLISHER_API_TOKEN" }
$job = Get-Content examples/job.json -Raw | ConvertFrom-Json
$job.account_id = "your_username"
$job.scheduled_at = (Get-Date).ToUniversalTime().ToString("o")
$body = $job | ConvertTo-Json
$result = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/v1/jobs -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))
Invoke-RestMethod -Uri "http://127.0.0.1:8080/v1/jobs/$($result.id)" -Headers $headers
Invoke-RestMethod -Uri http://127.0.0.1:8080/health -Headers $headers
```

`scheduled_at` — ISO 8601 с часовым поясом, например `2026-11-10T18:00:00+03:00`. Отсутствующее поле означает «сейчас». Просроченные задания исполняются при доступности worker. Windows и телефон должны быть включены; внешнее расписание и подготовка контента принадлежат оркестратору.

| publication_mode | Поведение |
| --- | --- |
| `TRIAL_REEL` | Включает Trial, выключает автоматическое распространение. Если функции нет — `FEATURE_UNAVAILABLE`. Никогда не заменяется обычной публикацией. |
| `NORMAL_REEL` | Выключает Trial, если переключатель доступен, и проверяет обычный режим. |
| `SHARE_TRIAL_TO_EVERYONE` | Только отдельное явное задание с `source_job_id` ранее успешно опубликованного LIVE Trial из этой базы, того же аккаунта/video_id/R2 key. Открывает сохранённый permalink, проверяет Trial и автора, использует штатную функцию Instagram. |

`caption` включает описание и хештеги, до 2200 символов. `execution_mode` по умолчанию `DRY_RUN`. Ошибка валидации — HTTP 422, конфликт содержимого одного `idempotency_key` — HTTP 409, запрос LIVE при отключённом разрешении — HTTP 403. Повтор идентичного запроса возвращает прежнее задание. Для точного воспроизведения сохраняйте исходный JSON запроса.

Пример перевода Trial: скопируйте исходные `video_id`, `r2_object_key`, `account_id`; задайте `publication_mode=SHARE_TRIAL_TO_EVERYONE`, `source_job_id=<trial job UUID>` и новый `idempotency_key`. Сначала используйте `execution_mode=DRY_RUN`. Если функция отсутствует, ограничение не обходится. Идентификатор задания DRY_RUN не подходит как источник реально опубликованного Trial.

## Ваше разрешение на LIVE

DRY_RUN подготавливает публикацию, проверяет Trial и останавливается **до финального подтверждения** со статусом `DRY_RUN_READY` и скриншотом. Он не превращается в LIVE автоматически. Интерфейс Instagram остаётся на подготовленном экране; сервис не гарантирует сохранение черновика после закрытия приложения.

После проверки скриншота/телефона остановите сервис, установите `$env:PUBLISHER_ALLOW_LIVE="true"`, убедитесь в `live_calibrated=true` и перезапустите. Отправьте **новое явное задание** с новым `idempotency_key` и `execution_mode=LIVE`. Сервис заново пройдёт подготовку и один раз выполнит финальное действие. Это и есть разрешение на конкретную публикацию; кнопки «автоматически продолжить DRY_RUN» нет. По окончании сеанса выключите LIVE и перезапустите сервис. Никогда не включайте автоматический перевод Trial в общую публикацию в самом Instagram.

## Состояния, восстановление и ограничения

`QUEUED → RUNNING → DRY_RUN_READY` либо `RUNNING → SUBMITTING → PUBLISHED`. Альтернативы: `FAILED`, `FEATURE_UNAVAILABLE`, `BLOCKED`, `UNKNOWN_RESULT`; код причины хранится в `error`.

SQLite использует WAL и `synchronous=FULL`. Для финальной кнопки UIAutomator2 только считывает границы уникального элемента; одно нажатие отправляется через ADB без повторов, чтобы библиотечное восстановление JSON-RPC не повторило клик. Координаты вычисляются из текущего селектора, а не задаются для экрана заранее. Перед финальным действием одной транзакцией сохраняются `submitted=1` и уникальная запись публикации `(account_id, video_id)`. Trial и NORMAL считаются одной первоначальной публикацией: смена режима/ключа не позволяет повторить отправку. Перевод Trial имеет отдельную уникальную запись. Записи после неизвестного исхода не освобождаются.

На устройство действуют OS-lock по serial и lock каталога данных (в пределах одного пользователя Windows). Не запускайте другие ADB/UI-инструменты и другую копию сервиса под другим Windows-пользователем. Один телефон должен всегда использовать одну и ту же SQLite; замена/удаление базы снимает защиту от повторов. Не копируйте живую SQLite отдельно от WAL; делайте согласованный SQLite backup при обслуживании.

Повторяются только явные временные ошибки до финального действия, максимум `PUBLISHER_MAX_ATTEMPTS` (по умолчанию 3), с backoff. Ошибки UI, аккаунта и ограничений не повторяются. После рестарта незавершённая подготовка возвращается в очередь; `SUBMITTING` переходит в `UNKNOWN_RESULT`, устройство ставится на постоянную паузу. После неизвестного исхода или капчи новые задания не запускаются до ручного resume. `UNKNOWN_RESULT` никогда не нажимает «Опубликовать» повторно, даже если вы не видите ролик сразу. В MVP нет автоматической сверки с сервером Instagram и нет гарантии exactly-once во внешнем приложении; используется консервативное правило «не более одной попытки финального действия».

При `BLOCKED` завершите проверку личности/капчу вручную в Instagram. При `UNKNOWN_RESULT` проверьте результат на телефоне и сохраните решение у оркестратора; не создавайте новый `video_id` ради обхода защиты. После проверки:

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8080/v1/device/resume -Headers $headers
```

Скриншоты и XML сохраняются в `data/jobs/<uuid>/`, путь возвращается в API. Там же лежит MP4; результаты — в `data/publisher.sqlite3`. Если телефон недоступен, скриншот может отсутствовать. Логи содержат job UUID, статус и безопасный код, без caption/секретов/полного текста исключения. Для сохранения консоли: `python -m android_publisher 2>&1 | Tee-Object -FilePath publisher.log`. Скриншоты/XML могут содержать персональные данные: ограничьте доступ к каталогу средствами Windows. Автоматическое удаление артефактов/видео не реализовано; обслуживайте хранилище вручную, сохраняя базу дедупликации.

```powershell
python -m pytest -q

```

CI: Ubuntu/Windows × Python 3.11/3.12, без телефона, R2-ключей и реальных публикаций. Покрываются API/авторизация, очередь и расписание, SHA256/manifest, DRY_RUN, явный LIVE, режимы Trial/NORMAL/перевод, дедупликация, барьер перед нажатием, неизвестный исход, пауза, ограниченные повторы, рестарт, аккаунт, блокирующие экраны, уникальность селекторов и отключение автоматического распространения.
